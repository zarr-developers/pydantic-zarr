The members an experimental v3 `ArraySpec` or `GroupSpec` does not declare are no longer pydantic extras. Read them from the read-only `spec.extra_fields` mapping (or `get_attribute(spec, "key")`) instead of `spec.key` or `spec.model_extra`. They still dump back as top-level members, a dump's `include` and `exclude` still name them by key, and `model_copy(update=...)` still sets them. A plain TypedDict held by an experimental v3 spec now drops unknown keys, as it does under any other model; declare it with `extra_items=` (PEP 728) to keep them. The experimental v3 metadata objects (`NamedConfig` and the chunk grid and chunk key encoding configurations) declare `extra_items=object`, so they still keep members such as `must_understand`. The experimental v3 module no longer defines `StrictBase`, and a subclass of its `NodeSpec` that sets `extra="allow"` is refused.
