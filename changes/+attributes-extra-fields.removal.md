The keys an `AttributesBase` model does not declare, and the members an experimental v3 `ArraySpec` or `GroupSpec` does not declare, are now kept in an `extra_fields` mapping, as the stable v3 specs already do, instead of as pydantic extras. They still dump back as top-level keys. Read them from `model.extra_fields["key"]` (or `get_attribute(model, "key")`) instead of `model.key` or `model.model_extra`. A plain TypedDict nested in attributes now drops unknown keys, as it does under any other model; declare it with `extra_items=` (PEP 728) to keep them. The experimental v3 metadata objects (`NamedConfig` and the chunk grid and chunk key encoding configurations) declare `extra_items=object`, so they still keep members such as `must_understand`.
