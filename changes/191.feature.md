The spec type parameters (`TAttr`, `TItem`) are now covariant, in v2 and v3: the specs are frozen, so both parameters appear only in read positions on instances, and a narrowed spec is substitutable for a wider one. The `Any*` aliases (`AnyArraySpec`, `AnyGroupSpec`, `AnyBaseGroupSpec`) become ordinary wide types (`ArraySpec[TBaseAttr]` and friends) instead of gradual-typing escapes, so attributes and members read through them — including the results of `resolve_path`, `from_flat` and the `is_*_spec` guards — keep checked types instead of `Any`; code that leaned on those reads being `Any` may need narrowing. The constructing classmethods (`from_array`) take `attributes: TBaseAttr` instead of `TAttr`, since a covariant parameter may not appear in argument positions: the argument is checked against the class's attribute type by validation rather than statically, which is the trade that keeps `Self` return types for subclasses.
