pydantic-zarr now requires zarr-metadata 0.9 and takes the spec values it exports instead of restating them: the v2 memory order and dimension separator checks narrow with `is_zarr_v2_array_order` and `is_zarr_v2_array_dimension_separator`, `pydantic_zarr.v3.NodeType` is an alias of `zarr_metadata.ZarrV3NodeType`, `pydantic_zarr.v2.FloatFillValue` uses zarr-metadata's `ZarrV2FloatSpecial`, and the data type, codec, chunk grid and chunk key encoding names `pydantic_zarr.v3` writes are zarr-metadata's `*_NAME` constants. `ArraySpec.with_sharding_codec` types `index_location` as `zarr_metadata.ShardingIndexLocation`. The error `pydantic_zarr.v2.parse_dimension_separator` raises now lists the permitted values as `('.', '/', None)`, and the JSON Schema of a v2 float fill value lists `"NaN"` first.
