pydantic-zarr now requires zarr-metadata 0.9 and takes the spec values it exports instead of restating them: the v2 memory order and dimension separator checks narrow with `is_zarr_v2_array_order` and `is_zarr_v2_array_dimension_separator`, `pydantic_zarr.v3.NodeType` is an alias of `zarr_metadata.ZarrV3NodeType`, and the default chunk key encoding is built from `DEFAULT_CHUNK_KEY_ENCODING_NAME` and `DEFAULT_CHUNK_KEY_ENCODING_DEFAULT_SEPARATOR`. The error `pydantic_zarr.v2.parse_dimension_separator` raises now lists the permitted values as `('.', '/', None)`.
