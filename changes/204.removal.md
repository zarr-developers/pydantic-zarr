pydantic-zarr requires `zarr-metadata` 0.8.0 or later, and reads its scopes only by their `*_CONTEXT` names. A v2 spec built without a fill value, or by `from_array` from an array with none, gets the default `zarr-metadata` 0.8.0 derives for its dtype, which is the value zarr-python uses, where 0.10.0 gave `0` for every dtype: `False` for `|b1`, `(0.0, 0.0)` for complex dtypes, the empty string for `|S` and `<U`, null bytes (in base64) for raw and struct dtypes, `"NaT"` for the time dtypes, and `None` for `|O`. A float dtype gets `0.0`, the same value as `0` written as a float.

`ArraySpec`'s fields (v3) are annotated with the types a spec holds: `codecs` as a tuple of codec objects (`AnyNamedConfig`), `chunk_grid` and `chunk_key_encoding` as named configurations, as 0.10.0 annotated them. The inputs validation converts (a bare codec or encoding name, a numpy dtype or scalar, a list, a typed core object such as `zarr_metadata`'s `RegularChunkGridObject`) are typed on the input paths instead: `create_default`, `replace` and `from_array` accept them, through the new `ChunkGridLike`, `ChunkKeyEncodingLike` and `FillValueLike` types and the input `TypedDict`s, and `model_validate` takes any document. A type checker now refuses those inputs in a direct `ArraySpec(...)` call, which still accepts them at run time. v2's `ArraySpecUpdate` likewise accepts numcodecs codecs, numpy scalars and sequences.
