`pydantic_zarr.v2.ArraySpec` now validates its fields as a whole Zarr V2 array metadata document, via `zarr-metadata`'s `ZarrV2ArrayMetadata`, as the v3 `ArraySpec` does. This is breaking for specs that were constructible before but describe invalid `.zarray` documents (for example an integer array with fill value `1.5` or `"NaN"`, or a bool array with fill value `3`): constructing them now raises a `ValidationError` listing every problem. A spec built without a fill value, or by `from_array` from an array with no `fill_value`, now gets the default for its dtype: `0` when the dtype accepts `0` and `None` otherwise (bool, complex, string and structured dtypes), the rule `zarr-metadata` uses. The default was previously `0` for every dtype. The new `pydantic_zarr.v2.dtype_default_fill_value` returns it.
