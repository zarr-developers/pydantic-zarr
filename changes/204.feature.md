`pydantic_zarr.v3.ArraySpec.create_default(**fields)` replaces `from_shape_and_data_type` (never released), and delegates to `zarr-metadata`'s `ZarrV3ArrayMetadata.create_default`: every field not given takes the default `zarr-metadata` derives from the fields given, in the class's scope. A shape brings one regular chunk covering the array, where `from_shape_and_data_type` guessed a chunk shape; pass `chunk_grid="auto"` for zarr-python's guess. A data type brings its default fill value and array -> bytes codec, so `pydantic-zarr` no longer keeps its own table of variable-length defaults: a spelling only another scope claims, such as `variable_length_bytes` outside `ZARR_PYTHON_CONTEXT`, gets no default fill value and needs one given. With nothing given, the array is a scalar `uint8`. A numpy data type is accepted and converted first, and the chunk key encoding stays the `default` one spelled as zarr-python writes it. `ArraySpecOverrides` becomes `ArraySpecCreate`.

The v3 default fill value, which `ArraySpec.from_array` uses for an array that has none, is the one `zarr-metadata` derives, as the v2 default already was: `0.0` for a float data type where it was `"NaN"`, `(0.0, 0.0)` for complex where it was `("NaN", "NaN")`, and `"NaT"` for the numpy time types where it was the int64 minimum (the same value). `pydantic_zarr.v3.dtype_default_fill_value` returns it.
