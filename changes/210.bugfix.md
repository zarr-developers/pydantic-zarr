Restored the `depth` parameter of `GroupSpec.from_zarr` and the module-level `from_zarr`, in `pydantic_zarr.v2` and `pydantic_zarr.v3`, which 0.11.0 removed without a deprecation period, so that calls written for 0.10, such as every read in `ome-zarr-models`, no longer raise `TypeError`. `depth` is deprecated along with the rest of the zarr-python IO and goes in 0.12. `depth=0` reads the group without its members into a `BaseGroupSpec`, parametrized with the calling class's attributes type and its `Annotated` validators, since a `GroupSpec` always holds its members. Code that reads the result's `attributes` (or other group metadata) keeps working; the result has no `members`, is not a `GroupSpec`, and validators and methods the calling class declares do not apply to it. Any other depth reads the whole hierarchy, since a `GroupSpec` cannot hold groups whose members were not read, and for a positive depth the deprecation warning says the depth was ignored: the read is no longer bounded, and a class whose member types are narrowed may refuse members 0.10 did not read. Use `from_zarr_flat(node, depth=n)` to read part of a hierarchy. A depth lower than -1 raises `ValueError`, as in 0.10.
