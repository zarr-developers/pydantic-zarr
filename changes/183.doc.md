Four worked examples join the documentation, one per real-world layout the API was exercised against: OME-Zarr 0.5 and 0.6 images, a GeoZarr Sentinel-2 product, and xarray-style datasets. Each shows the typed-attributes and typed-members patterns (closed `TypedDict` member sets, `AttributesBase` attribute models, `from_shape_and_data_type`, `resolve_path`/`get_path`, cross-member validators), round-trips its hierarchy through a store, and demonstrates the refusals the model enforces; each example is a self-contained, executable script under `examples/` (PEP 723 metadata included, so `uv run examples/<name>.py` works standalone) whose sections the documentation pages embed, executed whole by the documentation test suite — and each script proves its model by writing the hierarchy and comparing every stored metadata document, exactly, against what a reference implementation writes (xarray for the dataset layouts, `ome-zarr-py` for OME-Zarr 0.5, `ngff-zarr` for OME-Zarr 0.6).
 The Zarr V3 usage page gains a section on validation scopes: how the metadata document check judges each extension-point name by the definition that claims it, choosing the scope per call through the validation context, making it a property of the model with the `zarr_scope` class variable, and strict conformance with `zarr_scope_strict`, with executable examples for each.
