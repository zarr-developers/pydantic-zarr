`ArraySpec`, `BaseGroupSpec` and `GroupSpec` (v2 and v3) gain `to_stored_metadata_json()`, which returns the node's metadata as a Zarr store holds it: a mapping from each store key to the JSON document stored there, statically typed per key. For v3 that is `zarr.json`; for v2, `.zarray` or `.zgroup` plus `.zattrs`, written even when the attributes are empty, as zarr-python writes it. A `GroupSpec`'s mapping also holds every member's documents at any depth, at keys prefixed by the member's path (`"a/zarr.json"`, `"a/b/.zarray"`): the metadata documents `to_zarr` writes, so a consumer can write a hierarchy's metadata without zarr-python. The new classmethod `from_stored_metadata_json()` reads such a mapping back, with no store involved. The return types are `ZarrV3ArrayStoredJSON` / `ZarrV3GroupStoredJSON` and `ZarrV2ArrayStoredJSON` / `ZarrV2GroupStoredJSON`.
