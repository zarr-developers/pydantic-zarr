`pydantic_zarr.v3` reads every Zarr V3 array document `zarr-metadata` reads. `ArraySpec.chunk_grid` and `chunk_key_encoding` take any declaration, judged by its definition in the scope (the rectilinear grid `zarr-metadata` defines reads in the default scope; a class with `zarr_scope_strict` set still refuses a name nothing in its scope claims). Declarations read in every envelope spelling the spec allows, normalized to the canonical one: a bare name becomes `{"name": ...}`, an explicit `"must_understand": true` and an empty `configuration` are dropped, a data type object with nothing to configure becomes its bare name, and a configuration's JSON arrays become tuples, so specs built from different spellings compare equal. An extra field a reader does not recognize is accepted whenever it is an object that says `"must_understand": false`, kept as written, whatever else it holds; it no longer has to be a named extension object. This is how `zarr-metadata` reads the spec's rule and what its strategies draw.
