Fixed array creation failing under zarr-python 3.3+ with `ValueError: The 'endian' configuration needs to be specified for multi-byte data types.` The `auto_codecs` functions in `pydantic_zarr.v3` and `pydantic_zarr.experimental.v3` (used by `ArraySpec.from_array` when `codecs="auto"`) now emit `{"name": "bytes", "configuration": {"endian": "little"}}` for multi-byte data types, matching zarr-python's default, instead of an endian-less `bytes` codec. Explicitly declared endian-less `bytes` codecs are passed through unchanged, so materializing them with a multi-byte data type still raises zarr's error. Also added zarr-python 3.3.0 to the test matrix.
