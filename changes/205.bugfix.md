Fixed the experimental v3 `ArraySpec` dropping the `bytes` codec's `endian` configuration whenever the array's data type is single-byte, even when a `cast_value` codec earlier in the pipeline hands `bytes` a chunk of a multi-byte type, which left the document invalid. The endian is now dropped only when the chunk `bytes` receives is single-byte, following the data type through the codecs before it, in the outer pipeline and inside a sharding codec.
